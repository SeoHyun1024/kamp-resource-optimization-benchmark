📝 현재 문제점
---

- 피크 위험 분류 모델(Random Forest, XGBoost, CatBoost)은 성능 비교까지만 되어 있고, **어떤 변수가 피크 예측을 좌우하는지**는 모델 내장 importance로만 확인한 상태다.
  - 내장 importance(gain, split 횟수)는 편향이 있고, 서로 강하게 상관된 lag·rolling 변수들 사이에서 중요도가 나뉘어 해석이 어렵다.
- 변수 간 **상호작용**(예: 가동 시간대 × 지난주 같은 시각 전력)은 분석하지 않았다.
- 모델이 **피크를 놓치는 경우(FN)**와 **피크가 아닌데 경보하는 경우(FP)**가 어떤 공정조건에 몰리는지 모른다.
  - 그래서 저감방안(`results/peak_reduction_plan.md`)을 오류 패턴과 연결할 근거가 없다.
- test 구간은 양성 47건이고, 오류도 CatBoost 기준 FN 12건, FP 19건뿐이다. 이 표본만으로는 "오류가 집중되는 조건"을 통계적으로 주장하기 어렵다.

🛠️ 해결 방안 / 제안 기능
---

`notebooks/05_error_analysis.ipynb`를 추가해 03/04의 산출물을 그대로 읽고 아래 3가지를 분석한다.

1. **주요 영향변수**
   - SHAP으로 변수별 기여 방향과 크기를 확인한다.
   - Permutation importance는 PR-AUC 감소량 기준으로 잰다.
   - 상관된 변수는 그룹 단위 중요도로 함께 본다. 그룹은 전력이력 / 달력 / 생산·인력 / 기상 / 요금으로 나눈다.
2. **변수 간 상호작용**
   - SHAP interaction으로 상위 변수 쌍을 도출한다.
   - dependence plot과 2D PDP로 상호작용 형태를 시각화한다.
   - 후보 쌍: 시간대 × 지난주 같은 시각 전력, 시간대 × 주말/공휴일, 생산량 × 공장인원
3. **FN/FP 집중 공정조건**
   - 조건 구간(시간대, 요일, 주말·공휴일, 생산량·인원 분위, 직전 전력 구간)별로 FN rate와 FP rate를 비교한다.
   - 얕은 decision tree로 오류 규칙을 추출한다(예: "가동 시작 시간대 + 직전 전력 낮음 → FN 비율 높음").
   - FN과 TP, FP와 TN의 SHAP 차이로 오류 원인을 분해한다.
   - 임계값(179) 근처의 **경계 오류**와 **실제 오류**를 분리한다.
   - RF, XGBoost, CatBoost가 **모두 틀린 공통 오류**를 따로 정리한다.
   - 오류 표본을 확보하기 위해 train 구간에서 시계열 CV로 **OOF 예측**을 만들어 분석한다. test는 결론이 유지되는지 확인하는 용도로만 쓴다.
